# Student Performance Prediction System

A machine-learning web app that predicts whether a student is **Low-risk**, **Medium-risk** or **At-risk**,
and explains every prediction so faculty can step in early.

## How to run the app

### 1. Install Python
You need **Python 3.9 or newer**. Download it from https://www.python.org/downloads/.
On Windows, tick **"Add python.exe to PATH"** on the first screen of the installer.

Check it works by opening a terminal and typing:
```
python --version
```

### 2. Get the code
```
git clone https://github.com/maneeshkhandavalli/student-performance-analysis.git
cd student-performance-analysis
```
(Or click **Code → Download ZIP** on GitHub and unzip it.)

### 3. Start the app

**Windows (easiest):** double-click `run.bat`.

**Windows (terminal), macOS or Linux:**
```
pip install -r requirements.txt
python app.py
```
On macOS / Linux you can also run `bash run.sh`. If `python` is not found, use `python3` and `pip3`.

### 4. Open it in your browser
Go to **http://127.0.0.1:5000**

- The **first start takes about a minute**. The app generates the dataset (if missing) and trains the
  models, printing the accuracy of each model in the terminal. Later starts take about a second.
- Keep the terminal window open while you use the app. Press `Ctrl + C` to stop it.

### Quick test
On the **Predict** page click **Fill example**, then **Predict**. You should see the risk category,
a SHAP chart explaining the result, and suggestions.

### Troubleshooting
| Problem | Fix |
|---|---|
| `'python' is not recognized` | Reinstall Python with "Add python.exe to PATH" ticked, or use `py app.py` |
| `ModuleNotFoundError` | Run `pip install -r requirements.txt` again |
| Browser says "can't reach this page" | Wait a few seconds (first start is training) and refresh |
| Port 5000 already in use | Close the other program, or change the last line of `app.py` to `app.run(debug=True, port=5001)` |
| Want to retrain from scratch | Delete `model.pkl` and `metrics.json`, then start the app again |

## Features
| Page | What it does |
|---|---|
| **Predict** | Enter one student's details → risk category, probability for each class, SHAP explanation chart, improvement suggestions, *Save as PDF* |
| **Batch Upload** | Upload a CSV of many students → colour-coded results table + downloadable results CSV (a sample CSV is on the page) |
| **History** | Every prediction is saved in SQLite; filter by risk category and date |
| **Dashboard** | Model comparison, SHAP feature importance, class balance before/after SMOTE, prediction charts |

**Inputs used:** attendance %, study hours per week, continuous assessment average, assignments completed %,
mid-term marks, parents' education, extracurricular activities, internet access at home.

## Tech stack
- **Python**, **Flask**, Jinja2, SQLite
- **scikit-learn**: Logistic Regression, SVM, Random Forest, GridSearchCV, metrics
- **XGBoost**: the selected model
- **imbalanced-learn (SMOTE)**: fixes class imbalance (only 14% of students are at-risk)
- **SHAP** values via XGBoost's built-in TreeSHAP: explains each prediction
- **Bootstrap 5** and **Chart.js** (bundled in `static/`, so it works offline)
- **pytest**: automated tests

## How the model works (`train_model.py`)
1. Dataset: 1,200 student records (`students.csv`, generated by `generate_data.py`)
2. Stratified 70 / 15 / 15 split into train / validation / test
3. Each model runs in a pipeline with **SMOTE** applied only to the training folds (no data leakage)
4. **GridSearchCV** with 5-fold stratified cross-validation tunes each model on macro F1-score
5. The model with the best cross-validated F1 is selected. That's **XGBoost**.

### Results (test set, 180 students)
| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| Logistic Regression | 82.2% | 78.7% | 86.5% | 81.5% |
| SVM (RBF kernel) | 88.3% | 86.9% | 86.2% | 86.4% |
| Random Forest | 90.0% | 91.0% | 88.2% | 89.5% |
| **XGBoost (selected)** | **89.4%** | 88.2% | 90.4% | 89.2% |

- At-risk students correctly identified: **96%** (80% without SMOTE)
- Average response time: about 10 ms per prediction

Exact numbers can differ slightly on another computer because of library versions. The live values
are always shown on the app's **Dashboard**.

## Project structure
```
├── app.py               Flask web app (routes, validation, database)
├── train_model.py       Training, tuning and evaluation of the 4 models
├── explain.py           SHAP explanations
├── generate_data.py     Creates the dataset (students.csv)
├── students.csv         Dataset (1,200 students)
├── templates/           HTML pages
├── static/              Bootstrap, Chart.js, CSS
├── tests/test_app.py    Automated tests
├── docs/                Project report (PDF and Word)
├── requirements.txt     Python packages
├── run.bat              One-click start on Windows
└── run.sh               Start script for macOS / Linux
```
`model.pkl`, `metrics.json` and `history.db` are created automatically when the app runs and are
not stored in the repository.

## Note on the data
Real student records could not be used because of privacy. The dataset is generated to follow
realistic academic patterns (correlated scores, attendance penalties, class imbalance). To use real
data, replace `students.csv` with a file that has the same columns, delete `model.pkl`, and restart
the app.
